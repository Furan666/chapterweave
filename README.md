# ChapterWeave

ChapterWeave helps a book-club facilitator choose a title for two groups with different cultural starting points. The facilitator supplies one or two film, music, or book anchors for each group and a shortlist of three to six books they believe the club can obtain. Qloo ranks that **same shelf** separately for each group. ChapterWeave suggests a book only if it is in both groups' top half; otherwise it abstains and can look for clearly marked, unverified leads beyond the shelf. The facilitator must confirm availability before replacing a shortlisted book and comparing again.

This is a constrained planning workflow, not a claim that an algorithm knows individual members, predicts attendance, or checks library stock. Its particular use of Qloo is the independent comparison of two groups against one facilitator-controlled shelf, with explicit abstention and feedback. The interface does not compare raw affinity scores across separate Qloo queries.

## Try the example

The **Load illustrative live example** button selects previously resolved public Qloo catalog IDs for the films *Arrival* and *Interstellar* and four titles from [Brooklyn Public Library's book-club list](https://www.bklynlibrary.org/borrow/book-club-sets): *The Handmaid's Tale*, *Exit West*, *Americanah*, and *The Vegetarian*. It makes no API call until **Find a reading bridge** is pressed. From the result, **Change Group B to Parasite (2019)** keeps the other inputs fixed and lets the facilitator run a second comparison deliberately. Both groups are illustrative; current book availability is unknown, and Qloo ranks may change. Qloo responses are reused for up to seven days, with the earliest source-check time shown beside each result. **Explore a synthetic example** is a separate offline preview with invented books and no Qloo request.

For a Qloo-backed judge walkthrough, open the hosted site, select **Load illustrative live example**, advance to the shelf, and press **Find a reading bridge**. Inspect both groups' ranks for the same four books. Then press **Change Group B to Parasite (2019) · Compare again** and **Find a reading bridge** once more. The result view places the two observed plans side by side; the only changed input is Group B's film. If the new plan has no bridge, read the **Beyond the shortlist** result and its actual discover/compare/decision trace directly below the main outcome. If it offers a book, the facilitator must check availability before confirming it and comparing a revised shelf; if it finds no usable lead, report that result and revise the inputs. A hosted Qloo replay on 9 October 2026 returned *The Handmaid's Tale* at #1/#1 for Arrival/Interstellar, then abstained for Arrival/Parasite and surfaced *Steve Jobs* at #3/#3 as an **unverified** outside-shelf lead. Its availability and a revised-shelf plan were not verified. Judge the displayed source-check times and ranks, which may differ from that replay; do not infer actual stock or attendance from either plan.

## Source and local checks

- `public/` is the browser interface. All rendered catalog and result text is inserted as text, not executable HTML.
- `planner.mjs` builds bounded Qloo book queries and applies the shared-rank rule; `worker.mjs` holds the Qloo Search/Insights adapter used by the private backend.
- `deploy/backend/` contains the private Cloudflare Worker, rate limits, a shared lifetime Qloo-call budget, and a seven-day cache of successful official Search/Insights responses. `deploy/pages/` contains the static build and same-origin Pages proxy. The Qloo key belongs only in the backend's secret store.
- `*.test.mjs` and `deploy/staging.test.mjs` test the planner, adapter, browser example, private backend, budget, and proxy with synthetic responses; they do not call Qloo.

With Node.js 22 or newer (tested with 25.6.1) and npm, run:

```sh
npm ci
npm test
npm run preflight:backend
npm run build:pages
```

The build creates ignored `deploy/pages/dist/`. A local static server can serve `public/` to exercise the synthetic preview without a key. A live Qloo run requires the official event key and the configured private backend. Do not place a key in source control, the Pages project, browser code, screenshots, or `.env` files committed to a repository.

## Deployment and acceptance runbook

The private Worker has no public route, and the Qloo key is stored only as its encrypted Worker secret. The live [bmgg.eu demo](https://chapterweave.bmgg.eu/) uses a **120-call local lifetime budget**: the first 60 may serve general inputs, while the last 60 are reserved for the two exact built-in examples. The reserve is available to any anonymous visitor using those examples, not to identified judges. Valid Qloo Search/Insights responses are cached by exact URL for seven days. Until the judging window closes on 16 November 2026 at 11:45 p.m. Eastern, only the two built-in plans may replay older cached results when a temporary upstream 429/5xx/transport failure or the local call cap prevents refresh. The UI marks those results **Archived Qloo replay** and shows when Qloo data was last checked. Malformed upstream data, known 401/403 credential rejection, unrelated inputs, and replay after the cutoff fail closed. This narrow fallback follows the event's [cache guidance](https://github.com/qloo/qloo-hackathon-kit/blob/main/docs/API_ACCESS.md); it cannot prove an unknown key remains valid when local quota prevents contacting Qloo. The public [quota question](https://github.com/qloo/qloo-hackathon-kit/discussions/1) still has no confirmed issuer total, rate, expiry, or remaining-usage method. No book availability was verified.

1. From this directory, run the local checks above. In `deploy/backend/wrangler.jsonc`, confirm `QLOO_BUDGET` names the exported `QlooBudget` class, the `v1` migration creates it with `new_sqlite_classes`, `PER_IP_LIMIT` and `SITE_LIMIT` are configured, and `workers_dev` and `preview_urls` are false. The private Worker is already deployed; after source changes, deploy it with `npx wrangler deploy --config deploy/backend/wrangler.jsonc`. Confirm the SQLite Durable Object migration and both rate-limit bindings in the target account.
2. `QLOO_API_KEY` is already set only on `chapterweave-private-backend`. For a new deployment or key rotation, use `npx wrangler secret put QLOO_API_KEY --config deploy/backend/wrangler.jsonc` and its interactive prompt. This command deploys a new Worker version. Do not put the key in a command argument, Pages binding, repository, browser, screenshot, or log.
3. `chapterweave-pages` already serves the branded demo; create the project with `npx wrangler pages project create chapterweave-pages` only if it is absent in the target account. After changes, run `npm run build:pages` from this directory. Then run `npx --no-install wrangler pages deploy dist --project-name chapterweave-pages` **from `deploy/pages/`**, where `wrangler.jsonc` is picked up automatically. Confirm Pages has a `BACKEND` Service binding to `chapterweave-private-backend`; `deploy/pages/wrangler.jsonc` declares it. Redeploy Pages if the binding was added in the dashboard. The built `_worker.js` forwards only the four `/api/*` routes to the private Worker and serves other paths from `ASSETS`.
4. The Pages project has `chapterweave.bmgg.eu` as a custom domain, and authoritative DNS has a `chapterweave` CNAME to `chapterweave-pages.pages.dev`. HTTPS at the branded address returned 200. Preserve the domain's apex, nameservers, mail records, and other services.
5. At `https://chapterweave.bmgg.eu`, verify `/`, `/app.js`, and read-only `/api/status`. Status should report `configured: true` and local `used`, `remaining`, `generalRemaining`, and `freshEntries` counters without a Qloo call; these are not the issuer's quota or connectivity. In a separately budgeted live walkthrough, verify exact catalog choices, four-book coverage for both groups, source-check times, an honest pick or abstention, and the side-by-side comparison. A repeated cache hit should not advance the used count. The browser must never receive the event key or private Worker URL. Do not present a synthetic preview or an archived replay as fresh Qloo data.
